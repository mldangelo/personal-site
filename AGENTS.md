# AGENTS.md

Guidance for AI coding agents working on this Next.js personal portfolio site.

## Quick Commands

```bash
npm run dev          # Start dev server (localhost:3000)
npm run format       # Format with Prettier + Biome (run before committing)
npm run lint         # Biome linting
npm run type-check   # TypeScript checking
npm test             # Vitest tests
npm run build        # Production build + static export
```

**File-scoped (faster feedback):**

```bash
npx biome check path/to/file.tsx            # Lint single file
npm test -- ComponentName                    # Test single component
```

## Project Structure

```
app/                  → Pages, layouts, global CSS
app/styles/           → Modular CSS (tokens, base, components, layout, pages)
src/components/       → React components (organized by feature)
src/data/             → Static data (resume, projects, contact)
src/hooks/            → Custom React hooks
content/writing/      → Blog posts (Markdown with frontmatter)
src/data/writing.ts   → External writing links shown on `/writing`
public/images/        → Images and favicons
docs/                 → Documentation
```

## Code Style

**Do:**

- Use TypeScript strict mode, functional components with hooks
- Style with CSS custom properties in `app/styles/` (tokens in `tokens/`, components in `components/`)
- Keep components small and focused
- Use existing patterns from similar components
- Mark client components with `'use client'`
- Follow conventional commits: `feat:`, `fix:`, `chore:`, `docs:`
- Run `npm run format` before committing (CI enforces this)

**Don't:**

- Add new dependencies without clear need
- Create god components or monolithic files
- Hard-code colors—use CSS variables (`var(--color-*)`)
- Skip type annotations on function parameters
- Commit without running `npm run format` first

## Git Workflow

- Create a topic branch for every task; never commit or push directly to `main`
- Make small, frequent conventional commits as you go (e.g., `feat:`, `fix:`, `refactor:`)
- Push to your remote branch after every commit to keep it in sync
- Land changes on `main` by merging GitHub PRs with conventional-commit titles (deploys trigger automatically from these merges)
- If multiple PRs need to land together, open an integration branch PR; do not locally merge into `main`
- Treat `main` as protected: force-pushes and history rewrites require explicit user approval

## Key Patterns

- **Theming**: `data-theme` attribute on `<html>`, persisted to `window.localStorage` in client code/tests to avoid Node runtime globals leaking into browser-only paths
- **Static export**: `output: 'export'` for GitHub Pages—no server features
- **TypeScript 7 needs `experimental.useTypeScriptCli`**: TS 7 is the native compiler and does not expose the JavaScript compiler API Next uses for its build-time type check, so `next build` fails without that flag in `next.config.mjs`. The flag makes Next shell out to the TypeScript CLI instead. It still gates the build — verified by injecting `const x: number = 'string'` and confirming a non-zero exit with no `out/` produced. Re-verify that if the flag ever changes, because a silently-skipped type check is worse than an old compiler
- **Biome upgrades need `biome migrate`**: Biome errors, not warns, when `biome.json`'s `$schema` version disagrees with the CLI, so a version bump alone fails `npm run lint`. Run `npx biome migrate --write` with the upgrade. `linter.rules.preset` replaced the deprecated `recommended` field; this repo uses `"none"` and opts into rules explicitly
- **FontAwesome packages move together**: each carries its own `@fortawesome/fontawesome-common-types`, where `IconName` is a string-literal union that grows every release. Bumping one package leaves multiple copies and `IconDefinition` stops being assignable across them. Bump `fontawesome-svg-core`, `free-regular-svg-icons`, and `free-brands-svg-icons` in lockstep
- **The artifact actions are coupled pairs**: `upload-artifact` feeds `download-artifact`, and `upload-pages-artifact` feeds `deploy-pages`, both on the path that publishes the site. Dependabot proposes them individually; bump each pair together
- **`overrides` exist to reach security patches upstream pins away from**: `next` pins `postcss` to an exact version and declares `sharp` as an optional `^0.34.x`, so neither can reach its patched release through normal resolution — `package.json` `overrides` lift them. Re-check these on every `next` upgrade: once Next ships a range that already includes the fix, drop the override rather than leaving it to pin something backwards. The postcss override was verified inert by building before and after and diffing the emitted CSS byte-for-byte. The static site does not use Next's image optimizer, but `npm run og` renders committed cards through `next/og`, whose Node renderer dynamically loads Sharp; the card ledger therefore binds the locked Sharp entry alongside Next and React
- **Node baseline lives in three places**: `.nvmrc` (development plus the install/quality/test jobs), `engines.node` in `package.json` (what forks are told they can use), and the `build` matrix in `.github/workflows/node.js.yml` (literals — a matrix cannot read `.nvmrc`). The deployed leg is named once as the workflow-level `DEPLOY_NODE` env so the Pages-configure and artifact-upload gates cannot drift apart; a build step asserts `DEPLOY_NODE` still matches `.nvmrc`. Derive the `engines` floor from the tightest transitive requirement rather than guessing — `jsdom` currently forces `^22.13.0`, and `@testing-library/jest-dom` requires `>=22`, which is why Node 20 had to go
- **Production compiler**: `npm run build` intentionally passes `--webpack`. Turbopack's build tracer stalls on the build-time public-image header reader used by article rendering; keep development on Turbopack, but do not restore Turbopack production builds until this exact export completes promptly on the full CI matrix
- **Canonical/export URLs**: When generating absolute URLs for metadata, RSS, sitemap, or schema, match `trailingSlash: true` output (`/about/`, `/writing/post-slug/`) instead of non-canonical no-slash variants; file-like routes such as `/feed.xml`, `/sitemap.xml`, and `/resume.json` stay file-like
- **The résumé is published as data as well as a page**: `/resume.json` is a `force-static` route handler assembled by `src/lib/resumeJson.ts` from shared profile and résumé data, with mapping tests for the places where the JSON and page intentionally differ. That is what makes `work.ts`'s `Conforms to https://jsonresume.org/schema/` header consumable. `/resume/` exposes both a visible JSON link and an `application/json` metadata alternate, and the export verifier requires both. Two traps live here. The `summary` strings in `src/data/resume/work.ts` are Markdown **with inline HTML anchors** — `JobSummary` renders them through `markdown-to-jsx` — so anything consuming them as text has to flatten them; `toPlainText` strips only the known anchor tags for the artifact rather than stripping the source and costing the page its links. And JSON Resume sets `additionalProperties: false` only at the document root: nested objects allow extension properties, while types, URI formats, and date patterns still carry their own validation rules
- **`toPlainText` and the export gate have to promise the same thing**: `HTML_TAG` in `scripts/verify-export.mjs` rejects prose that still carries markup, and résumé prose is technical — a broad `<[a-z/]…>` fires on `Map<string, number>` and `vector<int>`, which `toPlainText` preserves on purpose. That combination is green on `npm test` and red on `npm run verify-export` in CI, blaming markup that was never written. Keep the gate an element-name whitelist requiring whitespace, `/`, or `>` after the name, keep unsupported elements such as `<canvas>` in it so a construct the conversion cannot yet strip still surfaces, and keep the agreement tests on both sides of it — the positive case in `scripts/__tests__/verify-export.test.ts` uses the same literal string as `src/lib/__tests__/resumeJson.test.ts`
- **Cross-file joins in `src/data/` match whole values**: `resumeJson.ts` files coursework under a degree by comparing `course.university` to `Degree.school` exactly, which is why `courses.ts` says "Stanford University" rather than "Stanford". Containment looks harmless with one school and silently publishes the same courses under every degree whose name contains another's. Assert cardinality across the whole document, not per entry — per-entry assertions never look at the duplicate
- **`verify-export.mjs` helpers take public paths, not routes**: `pageAt`, `exportedFileExists`, and `validateInternalTarget` all run their argument through `routeForPublicPath`, which strips the repository-site base path. `pageAt('/resume/')` therefore returns `undefined` on a base-path build while passing locally — wrap the route in `publicPathForRoute` first. The `basePath` fixture case in `scripts/__tests__/verify-export.test.ts` is what catches this. Native links to file-like routes need the same care: `/resume/` uses the document-relative `../resume.json`, and its component test resolves that rendered href at both root and repository paths
- **Page metadata**: Route-level `metadata` exports and `generateMetadata` should override `openGraph` and `twitter`, not just `title`/`description`, otherwise subpages inherit the homepage share card from `app/layout.tsx`; for `app/not-found.tsx`, omit `openGraph.url` because there is no stable canonical 404 route in the static export
- **Metadata objects replace, they do not merge**: a route-level `openGraph`, `twitter`, or `alternates` object wholly replaces the inherited one, so anything omitted vanishes from that page. This has caused three separate bugs — posts with no `og:image`, subpages with no image at all, and the writing index with no canonical after it declared RSS `types`. Spread `sharedOpenGraph` / `sharedTwitter` from `src/lib/metadata.ts`, and spread the existing `alternates` before adding to it. `app/__tests__/page-metadata.test.ts` pins all of it
- **Share images**: `npm run og` writes the site card at `public/og.png` and one card per published post at `public/og/writing/<slug>.png`, all 1200x630. Commit them together with `public/og.meta.json`, the ledger that records every image alongside the generator source, locked renderer packages, exact checksummed font files, profile facts, colour tokens, and each post's measured readout. `npm run og:check` runs two halves that fail for different reasons and are separate CI steps: `og:check:ledger` is hermetic, and `og:check:render` fetches the pinned fonts and re-renders byte for byte, so a red run reads as a network problem or a stale card rather than both at once. Together they fail when a card is stale, edited, missing, or belongs to no published post. Generation and the render check both refuse to run without Sharp: `next/og`'s Node renderer uses it when `import('sharp')` resolves and silently falls back to a bundled resvg.wasm when it does not, which changes every byte while the ledger still records Sharp's lock entry. Never resolve a mutable Google Fonts family endpoint while generating committed images: pin the versioned TTF URL and SHA-256 in `scripts/og-inputs.mjs`, and let generation fail if its bytes change. Inputs both scripts need live in that module — a fact only one of them knows silently stops being checked. Cards carry no amber and no live value: a baked PNG is frozen, so the signal colour would be lying. Do **not** convert any of this to an `app/opengraph-image.tsx` metadata route: it emits an extensionless file that GitHub Pages serves as `application/octet-stream`, which scrapers reject, and the file convention only reaches routes that do not declare their own `openGraph`
- **The share card and the article image are different images**: a post's `image` frontmatter is the representative screenshot or diagram, used for JSON-LD, where its real dimensions matter. `og:image`/`twitter:image` always point at the post's generated card, because `summary_large_image` wants 1.91:1 and an article screenshot is whatever shape it is
- **Fitting text into a generated card**: satori lays a card out and reports nothing back, so a title one line taller than expected silently collides with the readout rule. `og-layout.mjs` picks the display size from an estimate whose every assumption is the same constant the generator uses, and throws when the complete title and description cannot fit even at the minimum size. Never replace that failure with a minimum-size fallback: it turns cropped output into a successful generation. Two things make the estimate trustworthy. It wraps words one at a time using per-class character advances read from the pinned TTFs, because a single 0.5em average calibrated on mixed-case copy under-counted an all-caps title by a line; and the geometry constants are measured off rendered cards, not added up from the styles — `READOUT_HEIGHT` was 22px short of the real row for exactly that reason. Then `og-measure.mjs` decodes each rendered PNG and refuses to write a card whose ink reached the readout, so an estimate that is still wrong fails the build instead of publishing a cropped card
- **Drafts**: every read of a post goes through `isPublished` in `src/lib/posts.ts`, and `generateStaticParams` must use `getPostSlugs()` rather than raw filenames. Reading the directory directly is what once exported a full draft with `robots: index, follow`. Draft leaks are not only routes: `public/` ships verbatim. Keep draft-only screenshots and downloads outside it; the development route uses the generic card and may reserve a fallback ratio only for a missing root-relative draft image. `verify-export.mjs` parses the same inline, reference-style, relative, and passive raw-HTML resource forms as the renderer, resolves them from the post route, and fails when an asset referenced only by a draft appears in `out/`; active raw tags and uninspectable CSS/data documents fail closed. A plain Node script cannot import `isPublished`, but it can and must use the same dependency-free frontmatter validator in `src/lib/post-frontmatter.mjs`; validating after an asset reader has already skipped a draft makes malformed draft content pass one boundary and fail the other. The name check for draft-derived files is scoped to the two places a slug can only mean a draft — the generated-card directory and the draft's own `/writing/<slug>` route — because post slugs are ordinary words: matching every path segment made a draft called `about` fail the site's own `/about/index.html`
- **robots**: never emit a positive `index, follow` globally. It is already the default, and it contradicts any page that sets `noindex` — the 404 shipped carrying both
- **Static export constrains data fetching**: `output: 'export'` requires every route to be statically renderable, so build-time fetches must stay cacheable (`revalidate: false`). An uncached fetch silently forces the route dynamic, which makes it fall back on every build. Cache staleness is handled in the Pages workflow instead, which deliberately does not restore `.next/cache`
- **Filtering hides, it does not unmount**: `Skills` keeps every group in the DOM behind `hidden` so `print.css` can restore them. Removing filtered content from the DOM means a printed resume silently reflects whatever filter was selected
- **An accessible name needs a role that accepts one**: `aria-label` on a bare `<span>` or `<div>` is discarded, because the element maps to role `generic` — `SkillTag` shipped a proficiency announced to nobody that way. Prefer real text, visually hidden with `.sr-only` if it must not be seen, over an ARIA name
- **State is not outcome**: `aria-pressed` describes the control, not what the press did. A filter that hides most of a section in place should also associate the control with its result and announce the derived count — the skills filter reports "Showing N of M skills in \<category\>" through a polite, atomic status region. Keep that region `.sr-only`: printing un-hides every group, so a visible count would contradict the paper
- **Competency needs an explicit equivalent**: the old skill tags varied weight and text tone by their 1–5 self-score, while a numeric `aria-label` on a generic `<span>` was ignored. The current UI reduces that score to `deep` / `working` / `familiar`, explains the knowledge tiers once in a legend, and repeats each tag's description in `.sr-only` text. Keep all three in sync. Because the legend's samples wear `.skill-tag--*` _without_ `.skill-tag`, each tier modifier must state its own `color` rather than leaning on the base class — a modifier that only set a weight made the legend show the working tier in the familiar colour, in both themes and on paper. The former per-category `color` field was unrelated to competency and produced the same decorative tick for every category
- **Theme images**: Use `ThemePortrait` component for light/dark variants
- **Profile copy**: Keep role/bio updates in sync across `src/components/Template/Hero.tsx`, `app/layout.tsx` metadata, `src/data/about.ts`, and `src/data/resume/work.ts` so homepage copy, SEO, schema, and resume stay aligned
- **Long-form markdown pages**: Prefer a dedicated renderer component that can parse markdown into semantic sections instead of styling raw headings globally; if `markdown-to-jsx` causes dev/runtime issues in App Router, a `'use client'` boundary may still be required even without hooks. Preserve stable heading ids when converting markdown headings so deep links and `scroll-margin-top` behavior keep working, prefer a shared helper over duplicating slug logic in each page component, and expose those anchors in the UI with section nav or self-links if readers are expected to use them
- **`markdown-to-jsx` shapes the DOM more than it looks**: three of its defaults have each caused a bug in `src/components/Writing/PostContent.tsx`. It **slugifies headings itself**, and its slugifier keeps every separator it strips, so a heading containing a code span of `--dangerously-skip-permissions` produced `on-using---dangerously-skip-permissions` while the rest of the site derived `on-using-dangerously-skip-permissions` from `createHeadingId`. Plan every Markdown id before rendering, reserve every emitted id so an authored `repeat-2` cannot collide with a generated suffix, retain one non-conflicting alias for each legacy published heading id, and leave non-heading ids such as footnotes on the renderer's original slug scheme. It **wraps a standalone image in a `<p>`**, so a `<figure>` has to be produced by the `p` override (a `<figure>` inside a `<p>` is hoisted out by the parser and breaks hydration) — discriminate on the single child's element type being the `img` override component, recursing one level for a linked image. Do not discriminate on the presence of a `src` prop: overrides apply to raw HTML too, so `<video src="/demo.mp4">` on its own line matched that test, became a `<figure>`, and was sent to the build-time image sizer — which only ever measures Markdown image syntax — failing `next build` outright. And it **wraps a multi-block document in a `<div>`**, which becomes the only child of `.prose`, so any `.prose > *` rule silently lands on the wrapper and constrains everything inside it; `wrapper: null` removes it. `forceBlock: true` keeps single-block content on the same path as everything else
- **Standalone image titles are the site's caption convention**: CommonMark defines the optional string in `![alt](src "title")` as an image title, not a caption. `PostContent` deliberately promotes that title to a visible `<figcaption>` for a standalone image, and drops it from the `<img>` once promoted — otherwise the same sentence is a native tooltip and the image's accessible description sitting directly above the caption a reader can already see. An image that stays inline keeps its tooltip. The signal travels by context (`CaptionedFigure`) rather than a cloned prop, because a linked figure puts the image one level below the promoted node. Keep the authoring convention, parser, renderer, and tests aligned
- **`max-width` cannot widen a block**: a block at `width: auto` fills its containing block, so raising `max-width` alone does nothing — this is why wide article figures stayed at 640px. A figure that must exceed the reading measure needs an explicit `width`, and the prose blocks (not the article element) must be what carries `--measure-read`, or there is nothing to grow into. For measured local images, `--figure-width` is the build-time intrinsic width, so `min()` against it prevents upscaling; remote images still use the documented fallback dimensions
- **Blog posts**: Markdown files in `content/writing/` with frontmatter (title, date, description); slug derived from filename
- **Writing page**: Add external links in `src/data/writing.ts` and keep dated entries sorted newest first; local posts still live in `content/writing/`
- **Projects register**: `/projects` is one register in two parts, split by `status` in `src/data/projects.ts` — `shipped` renders publicly as “Selected work” in dated rows with no imagery, while `archive` renders earlier projects as cards. Every shipped entry declares a `sourceWork`; `src/data/__tests__/projects.test.ts` cross-checks its dates and numeric claims against that specific `src/data/resume/work.ts` role. That establishes internal consistency, not external truth or link health; research public claims from primary sources and check destinations live. A project may outlive the role that started it (Promptfoo continues at OpenAI), so `ongoing` describes the project and the subtitle must make a historical role explicit. Live entries sort by their own start dates before finished work; finished entries sort by their end or one-off dates, with title as the deterministic tie-break. `image` is optional and the card drops the frame when it is absent — never ship placeholder art, and never leave an entry with no public `link` looking clickable
- **A page not in `primary` routes is nearly unreachable**: `src/data/routes.ts` `primary: false` removes a route from the header nav and the mobile menu, leaving the footer as its only inbound path — and `/contact` passes `hideFooter`, so from there such a page is reachable from nowhere at all. Demote a route only when that is the intent
- **Design system**: Three type roles, and every element should pick one deliberately: `--font-display` (Bricolage Grotesque) for names and headings, `--font-body` (Newsreader) for prose, and `--font-mono` (JetBrains Mono) for data, dates, labels, and buttons. Structure is carried by hairlines (`--rule`) and near-square radii, not by shadow and float. A heavy `--color-fg-bold` rule opens a section; a `--color-border` hairline divides within one
- **Page measures are semantic**: use `--measure-wide` for split hero compositions, `--measure-page` for default pages/lists/footer, and `--measure-read` for continuous prose and compact data views. Component constraints such as portraits, controls, and short status messages may still use their own intrinsic measure; do not create a new page width for each route
- **Signal colour discipline**: `--color-accent` (ultramarine) is for structure and links. `--color-signal` (amber) is reserved for values that are live or in progress — the ticking age, a role with no end date. Using it decoratively is what makes the rest of it stop meaning anything. `--color-signal` is the text-safe value; use `--color-signal-mark` for non-text marks only
- **Link accents and button fills are different tokens**: `--color-accent` is tuned for text on the page background and is far too light in dark mode to sit behind white text (it measured 2.67:1). Filled controls use `--color-accent-fill` / `--color-accent-fill-hover` with `--color-on-accent`
- **`--color-fg-muted` is not a text colour**: it measures 3.41:1 on paper, under the 4.5:1 AA floor, and exists for non-text marks — the hover-revealed `#` glyph, a `li::marker`. Secondary text, including every 11px mono label, takes `--color-fg-light` (6.1:1 on the page, 6.3:1 in dark mode); where that flattens a hierarchy, recover the step with weight and tracking as `.project-card-subtitle` does, not by lightening the ink. Dark mode hides the failure — the same token measures 5.33:1 there — so check contrast in light mode
- **Focus rings use semantic tokens**: `--color-focus-ring` is the page-surface ring; `--color-focus-ring-fill` is the ring around accent-filled controls. Use those tokens in every explicit `outline` or `outline-color` declaration instead of bypassing them with palette values
- **Contrast tests are a design floor, not a conformance claim**: `--color-signal-mark` deliberately clears 3:1 against both paper surfaces, even though the visible `Present` text already carries the current-role meaning and WCAG 1.4.11 does not require a redundant graphic to do so. `contrastRatio` in `src/lib/contrast.ts` accepts only opaque hex; translucent colours need an explicit backdrop and compositing. Real surfaces still require rendered QA because grain, filters, and blending are outside the token calculation
- **Forced colors is a mode override, like dark and print**: `app/styles/forced-colors.css` is imported after `dark-mode.css` and before `print.css`. Forced colors removes gradient background images, which erases the global paragraph-link underline, but URL-backed images can remain — the paper-grain data URL is hidden explicitly. Preserve state with shape or system colours such as `ButtonFace`/`ButtonText` and `Highlight`/`HighlightText`. Only `border-color` and `outline-color` are remapped for you, so anything drawn with `background` needs an explicit rule — the timeline spines and the three hamburger bars each went invisible that way. Restate the higher-specificity variants too (`.jobs-container:last-child::before`, `.hamburger-button:focus-visible .hamburger-icon span`), or the original selector wins and the element disappears again in that one state
- **Interactive labels use `--text-ui` (13px)**, not `--text-2xs` (11px). 11px is for genuinely secondary annotation only — dates, gutter markers, category labels
- **Fonts must be variable and self-hosted**: `app/fonts.ts` feeds versioned Fontsource variable files to `next/font/local`, preserving metric-adjusted fallbacks and critical preloads without a Google build dependency. The weight tokens only render as distinct weights because those files remain variable. Newsreader italic is scoped through `app/writing/layout.tsx` and deliberately is not preloaded site-wide
- **Type sizes are rem**: `--text-*` are absolute so nesting never compounds. Avoid reintroducing `em` sizes
- **Telemetry**: Measured values shown on `/stats` live in `src/lib/telemetry.ts`. `useLiveAge` receives the exact server-rendered snapshot, writes the higher-precision age to `textContent`, and holds only the static/live status in React state. At `AGE_PRECISION_FULL` the timer reaches the 25ms floor, so routing the value through state would cause 40 component renders a second. Keep the no-rerenders-per-tick test, but do not pin an exact mount render count because Strict Mode may replay effects
- **A live readout must be truthful in every state**: `/stats` once shipped `--.-----------` to crawlers, no-JavaScript readers, and printed copies. The server now renders a two-decimal age snapshot with an `as of YYYY-MM-DD` note, then the client upgrades it in place. Thread the server string through as a prop, reserve the full-precision width in `ch`, and keep the note line mounted to avoid a hydration shift. `data-live="true"` and `--color-signal` mean an active timer; hidden pages and reduced-motion users keep the dated snapshot in ordinary ink
- **Build provenance is not `pushed_at`**: GitHub's repository `pushed_at` can run ahead of the site whenever any branch is pushed or a build fails. The stats page labels that fact as a repository push and separately reports `Built from commit` plus a UTC build date. `buildIdentity()` accepts only a complete `BUILD_SHA` / `BUILD_REPOSITORY` pair or a complete GitHub runner pair; never combine sources or infer a repository for an orphan SHA. Measured source links use the same repository and full immutable SHA. Dates published by a build go through `utcDate`, not a host-local formatter
- **Hierarchy from data**: Where a list needs varying visual weight (e.g. `tierFor` in `src/components/Resume/Experience.tsx`), derive it from the data — dates, role titles — rather than hardcoding per-item styling, so new entries place themselves
- **About-page log markers mirror the source**: `src/lib/logEntry.ts` reads only an entry's opening sentence and displays only the year, age, or range the prose explicitly states; never derive an exact counterpart from `profile.birthDate`, because a year-only event can span two ages and an age can span two calendar years. Lift a leading marker only when removing it preserves every qualifier—`In the summer of 1996` stays in the body and is annotated in place. Keep inline patterns anchored to real date phrasing so text such as `approximately 50 countries` or the model name `Tandy 2000` cannot become a marker. `I was` is the loose one — it precedes durations and counts as often as ages, so `INLINE_AGE` rejects a number followed by a measure noun or a second number (`I was 6 months into…`, `I was 1 of 3 founders…`) and leaves the gutter empty. Guard that with a negative lookahead, not a positive one: requiring a following `,`/`.`/`when`/`and` drops valid comma-less phrasing such as `When I was 12 I set a record`. Inline gutter copies are `aria-hidden` because the body still contains the full fact; lifted leading markers remain exposed. Keep `Some History` ordered chronologically by each entry's starting marker, and update the real-content tests when adding a new phrasing
- **Numbers about the site**: Never type a figure describing the codebase into a data file. `/stats` claimed 2,272 lines against ~4,400 actual before it was switched to `countSourceLines()` in `src/lib/loc.ts`. Anything countable should be counted at build
- **Motion**: Anything that animates continuously must check `prefers-reduced-motion` through the shared `usePrefersReducedMotion` hook (see `useLiveAge`, `EmailLink`) rather than hand-rolling a `matchMedia` read — the hand-rolled ones drifted, and only some of them subscribed to changes. The live age readout takes a single reading under the preference rather than ticking. Reduced motion should affect movement, not static decoration: do not hide the non-animated paper grain in that media query
- **Stats readings**: every row resolves through `resolveReadings` in `src/lib/readings.ts`, which formats counts, appends units, and carries provenance (`measured` / `github` / `profile`) so both tables describe their sources the same way. Format and value-derived link functions belong to the declaration and must be resolved before crossing the server/client boundary. Pin the locale on numeric counts and the time zone on absolute timestamps. Append a unit only where the label does not already name it (`29 packages`, but not `53 countries` or `301` beside “Lockfile package locations”). A measurement may be a React element when the server supplies a narrow client leaf such as `LiveAge`
- **Career chronology is derived, never hand-maintained**: `src/lib/career.ts` owns the resume timeline. `sortPositions()` orders roles by recency of involvement (end date first); an open-ended `commitment: 'part-time'` role is placed by its start so a long-running side engagement does not outrank later primary jobs, and `tierFor()` never promotes that side role to the lead visual tier. Source order in `src/data/resume/work.ts` is not load-bearing only because every consumer derives: anything meaning "the job I hold now" — the footer on every page, the JSON-LD `Person` node — calls `currentPosition()`, never `work[0]`. Both of those did index position 0, so a job change recorded the natural way (close the old role in place, append the new one) would have left every page still naming the previous employer; `src/lib/__tests__/current-role.test.tsx` pins them to the lead of the rendered spine against a fixture whose current role is deliberately last. `positionDuration()` derives each tenure, while `careerSpanYears()` is only the elapsed span since the earliest role—not summed active experience—so public copy must call it a career span. Both are measured at build time and there is no scheduled rebuild, so an ongoing tenure renders with a trailing `+` (and "or more" in its `.sr-only` label) the way the span does: a floor, not a claim. The page reads `Date.now()` once and threads it down; `Job` requires that shared instant. Visible duration abbreviations have an unabbreviated `.sr-only` label. Ordering compares validated `YYYY-MM-DD` strings directly rather than parsing to `Date`
- **Opting out of base link styles**: `app/styles/base/links.css` paints an accent underline on every `p a` / `li a`. Navigation-like links must set `background-image: none` or they pick up a rule that appears nowhere else — this is what made the mobile menu look broken
- **Print**: `app/styles/print.css` is imported last so it can override both themes. The resume is the page people print; check it there after changing resume layout
- **Page transitions must be deliberate and consistent**: the removed `app/styles/utilities.css` opted native same-origin navigations into a root cross-fade with `@view-transition`, but normal internal navigation goes through Next `<Link>` and bypassed that cross-document path. If transitions return, choose and test a trigger that covers the intended routes and add explicit reduced-motion behavior; options include `@view-transition`, `document.startViewTransition()`, React `<ViewTransition>`, and Next's deeper experimental integration. Do not leave comment-only placeholder stylesheets behind either — `components/forms.css` sat in the import graph and shipped nothing
- **Print reveals hrefs, which makes resume URLs user-visible text**: the `attr(href)` rule in `print.css` covers only the _identifying_ link of a professional or education entry — `.job-company` and `.degree-container .school a` — deliberately not citations inside a role summary (three URLs in one sentence of 10pt serif), not `.resume-print-contact` (its link text is already the readable address), and not course links. Chrome preserves anchors as clickable PDF annotations, while printing all 13 raw catalogue URLs made the paper version dense and broke hostnames across lines. The global `a { background-image: none !important }` does not override the pseudo-element because it declares no `content`. Validate link ownership as well as syntax: retired company domains may be unregistered or hijacked, so point them at a stable, trusted retrospective profile instead of following an unrelated redirect chain, and take a course's title and its link from the _same_ record — an old class site is often an archived offering under a title the catalogue has since retired. `app/__tests__/print-resume.test.tsx` pins the selector coverage, exclusions, screen-chrome suppression, known retired-company destinations, and link-data invariants. Exclusions are a property of the whole stylesheet, so they are asserted across every `attr(href)` rule with the rule count pinned, not against the first match

## Testing

Tests live in `__tests__/` directories adjacent to the code they test. Run `npm test` before committing.

```bash
npm test                        # Run all tests
npm test -- --watch             # Watch mode
npm test -- ComponentName       # Run specific test
```

`vitest.config.ts` pins `TZ` to a non-UTC zone for the whole run. Every CI runner is UTC, where a UTC-pinned formatter and a host-local one produce identical strings — so a date guard written on a UTC host asserts nothing on the machines that publish the site. Keep it set, and be wary of any test whose assertion restates the implementation (`toBe(x.toLocaleString('en-US'))`): pin the literal the reader would see instead, or the guard can never fail.
